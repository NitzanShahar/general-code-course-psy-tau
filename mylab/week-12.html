עבודה עם AI ב: סוכנים, Git ופרטיות

השבוע נעבוד עם סוכן קוד כמו בפרויקט מחקר אמיתי — וזה גם השבוע שבו כל מה שלמדנו על Git מקבל משמעות חדשה.

סוכן קורא ועורך את הקבצים שלנו בעצמו, ולכן Git הופך לרשת הביטחון: commit לפני כל צעד, git diff כדי לראות מה בדיוק השתנה, ו-git restore כדי לחזור לנקודה התקינה. נכיר את המושגים API ו-JSON, שדרכם הכלים האלה מדברים עם מודל השפה, ונלמד לשמור מפתחות וסודות מחוץ לקוד, במשתני סביבה ובקובץ .env. ולבסוף — פרטיות הנבדקים, כללי האתיקה ושקיפות בדיווח על שימוש ב-AI.

הפרק נסגר בתרגול של המושגים ובהתנסות מודרכת בפרויקט קטן עם סוכן — כדאי לעשות אותה לפני המטלה. מי שרוצה להעמיק יכול ללמוד גם איך פונים למודל שפה מתוך קוד פייתון.

קוד 7.9Git כרשת ביטחון

הנחיה למתרגל AI

בשיעור זה ארצה להבין איך Git, שכבר הכרתי, הופך לרשת הביטחון שלי כשסוכן עורך את הקבצים שלי. הפקודות רצות ב-Git Bash או בטרמינל המובנה של Cursor.
1. הסבר את הכלל: commit לפני כל צעד של הסוכן, כדי שתמיד תהיה "נקודה תקינה אחרונה" לחזור אליה:
git add .
git commit -m "load and describe stroop data"
2. הסבר שלוש פקודות לבדיקה אחרי שהסוכן עבד:
git status
git diff
git log --oneline
status מראה אילו קבצים השתנו מאז ה-commit האחרון, ואילו קבצים חדשים נוצרו (Untracked). diff מראה בדיוק אילו שורות השתנו: - לשורה שנמחקה ו-+ לשורה שנוספה (יוצאים מהתצוגה עם q). log --oneline מציג את ה-commits, כל אחד בשורה עם מזהה קצר.
3. הסבר rollback (חזרה לאחור): כשהסוכן עשה בלגן, לא מתקנים ביד שורה אחר שורה — חוזרים למצב של ה-commit האחרון:
git restore .
git restore analysis.py
הסבר שהשורה הראשונה מחזירה את כל הקבצים במעקב, והשנייה קובץ אחד. אזהרה: שינויים שלא נשמרו ב-commit נמחקים לצמיתות, ולכן מריצים קודם status ו-diff. הסבר שקבצים חדשים שהסוכן יצר לא נמחקים כך: רואים אותם ב-status ומוחקים ביד אם צריך.
4. הסבר מה עושים אם כבר עשיתי commit לשינוי רע: מוצאים את המזהה ב-git log --oneline ומריצים git revert עם המזהה. הפקודה יוצרת commit חדש שמבטל את הישן, בלי למחוק היסטוריה.
5. הסבר למה commits קטנים ותכופים עם הודעות ברורות הם מה שמאפשר את כל זה, ולמה Git עדיף על נקודות השחזור של Cursor: הוא עובד עם כל כלי, ונשמר גם ב-GitHub.
6. סכם בארבע שורות את מה שהוסבר, וכתוב ששלב הלימוד הסתיים.
הצג את השלבים האלו אחד אחד לפי הסדר. אחרי כל שלב עצור וחכה שאכתוב „המשך״. בשיעור הזה רק מסבירים: אל תשאל אותי שאלות ואל תיתן לי תרגילים — התרגול נמצא ביחידה נפרדת.

קוד 7.10API ו-JSON

הנחיה למתרגל AI

בשיעור זה ארצה להבין שני מושגים שמופיעים כמעט בכל פעם שקוד מדבר עם שירות אחר: API ו-JSON. רק מושגים, בלי לכתוב קוד.
1. הסבר מהו API (Application Programming Interface, "ממשק תכנות יישומים"): "שקע" מוסכם שדרכו תוכנה אחת מדברת עם תוכנה אחרת. כמו שקע חשמל: לא צריך לדעת איך תחנת הכוח עובדת, רק לחבר תקע בצורה הנכונה. תוכנה אחת שולחת בקשה (request) בפורמט מוגדר, ומקבלת תשובה (response).
2. תן שלוש דוגמאות ממחקר: מאגר נתונים (להוריד נתונים מפלטפורמת ניסויים מקוונת), חיפוש ספרות (לשלוף פרטי מאמרים ממאגר כמו PubMed), ומודל שפה. הסבר שגם Cursor עצמו שולח את ההודעות שלי ואת חלון ההקשר למודל דרך API, ושאפשר גם לפנות למודל מתוך סקריפט שלי.
3. הסבר שבדרך כלל ה-API נמצא בשרת באינטרנט, ושכדי להשתמש בו צריך לרוב מפתח API (API key): מחרוזת סודית שמזהה אותי, ולפעמים השימוש עולה כסף. על שמירת המפתח נדבר ביחידה הבאה.
4. הסבר מהו JSON: פורמט טקסט לשליחת נתונים בין מערכות, שבנוי מזוגות של מפתח וערך. הצג רשומה של נבדק:
{"id": 7, "group": "control", "age": 24, "completed": true, "rt": [512, 689, 478]}
והסבר כל חלק: סוגריים מסולסלים עוטפים רשומה; כל מפתח בגרשיים; ערך יכול להיות מספר, טקסט, true או false, או רשימה בסוגריים מרובעים. הסבר שזה מקביל ל-dict בפייתון ול-list עם שמות ב-R, ושזה קובץ טקסט כמו csv — אבל בניגוד ל-csv הוא יכול להכיל מבנה מקונן, כמו רשימת זמני תגובה בתוך רשומה של נבדק.
5. הסבר את הקשר: כשתוכנה פונה ל-API, הבקשה והתשובה נשלחות לרוב כ-JSON. ספר שגם קובץ מחברת (.ipynb) הוא קובץ JSON.
6. סכם בארבע שורות את מה שהוסבר, וכתוב ששלב הלימוד הסתיים.
הצג את השלבים האלו אחד אחד לפי הסדר. אחרי כל שלב עצור וחכה שאכתוב „המשך״. בשיעור הזה רק מסבירים: אל תשאל אותי שאלות ואל תיתן לי תרגילים — התרגול נמצא ביחידה נפרדת.

קוד 7.11סודות ומשתני סביבה

הנחיה למתרגל AI

בשיעור זה ארצה להבין איך שומרים מפתח API וסודות אחרים מחוץ לקוד, כדי שלא יגיעו ל-GitHub.
1. הסבר שמפתח API הוא כמו סיסמה: מי שמחזיק בו יכול להשתמש בשירות על חשבוני. הסבר את הטעות הנפוצה: לכתוב את המפתח בתוך הסקריפט, ולעשות commit ו-push. מרגע זה הוא ציבורי — גם אם מוחקים אותו אחר כך הוא נשאר בהיסטוריה של Git — ויש תוכנות שסורקות את GitHub ומחפשות מפתחות. אם זה קרה: מבטלים את המפתח באתר של השירות ומייצרים חדש.
2. הסבר מהו משתנה סביבה (environment variable): משתנה שמוגדר מחוץ לקוד, בסביבה שבה התוכנה רצה, וכל תוכנה שהופעלה ממנה יכולה לקרוא אותו. הזכר שכבר פגשתי כאלה בטרמינל: PATH ו-SHELL. הראה ב-Git Bash:
export MY_API_KEY="abc123"
echo $MY_API_KEY
והסבר שהגדרה כזו נעלמת כשסוגרים את החלון.
3. הסבר מהו קובץ .env: קובץ טקסט בתיקיית הפרויקט, עם שורה לכל סוד:
MY_API_KEY=abc123
הסבר שהקוד טוען ממנו את הסודות כמשתני סביבה — בפייתון עם החבילה python-dotenv, וב-R עם החבילה dotenv או הקובץ .Renviron — וקורא אותם בשם בלבד: os.getenv("MY_API_KEY") בפייתון, Sys.getenv("MY_API_KEY") ב-R. בקוד מופיע רק השם, אף פעם לא הערך.
4. הסבר את השלב הקריטי: להוסיף את השורה .env לקובץ .gitignore לפני ה-commit הראשון, ולוודא עם git status שהקובץ לא מופיע.
5. הסבר איך עובדים עם סוכן: לכתוב בקובץ ההנחיות "Load API keys only from environment variables; never write keys in code", ולא להדביק מפתח בצ'אט. הסבר ש-Cursor מסתיר מהסוכן כברירת מחדל קובצי .env וקבצים שב-.gitignore, ושאפשר להוסיף עוד בקובץ .cursorignore — אבל זו לא הגנה מלאה, כי פקודות טרמינל שהסוכן מריץ עדיין יכולות לקרוא אותם.
6. סכם בארבע שורות את מה שהוסבר, וכתוב ששלב הלימוד הסתיים.
הצג את השלבים האלו אחד אחד לפי הסדר. אחרי כל שלב עצור וחכה שאכתוב „המשך״. בשיעור הזה רק מסבירים: אל תשאל אותי שאלות ואל תיתן לי תרגילים — התרגול נמצא ביחידה נפרדת.

קוד 7.12פרטיות, אתיקה ושקיפות

הנחיה למתרגל AI

בשיעור זה ארצה להבין את השיקולים האתיים בשימוש בבינה מלאכותית במחקר: פרטיות הנבדקים, כללים ומדיניות, ושקיפות.
1. הסבר שכשמדביקים טקסט בצ'אט או נותנים לסוכן לקרוא קובץ, התוכן נשלח דרך API לשרתים של חברה חיצונית. לא תמיד ברור איפה הוא נשמר, לכמה זמן, ואם ישמש לאימון מודלים. בחלק מהכלים יש הגדרות פרטיות, ולמוסדות יש לפעמים הסכמים מיוחדים עם החברות.
2. הסבר מהם נתונים מזהים: שם, תעודת זהות, טלפון, כתובת, תאריך לידה, הקלטות ותמונות, ולעיתים גם שילוב של כמה פרטים (גיל, מקצוע ויישוב). הסבר שלא מעלים אותם לכלי בינה מלאכותית בענן, ומה החלופות: לתת רק שמות עמודות, לעבוד עם הסוכן על נתונים מדומים במבנה זהה ולהריץ את הקוד הסופי על הנתונים האמיתיים בעצמי, או להשתמש בכלי שהאוניברסיטה אישרה. הסבר שסוכן קורא קבצים בתיקייה הפתוחה, ולכן נתונים אמיתיים לא נמצאים בתיקייה שבה הוא עובד.

5. סכם בארבע שורות את מה שהוסבר, וכתוב ששלב הלימוד הסתיים.

קוד 7.14התנסות: פרויקט קטן עם סוכן

בשיעור זה ארצה לנסות בעצמי לעבוד עם סוכן קוד בצורה אחראית. אני עובד/ת על Windows, עם Cursor ו-Git Bash, ופייתון עם pandas מותקנים אצלי. הפעולות קצרות.
1. הנחה אותי בפעולות שלמטה, אחת בכל פעם. אחרי כל פעולה עצור, ובקש ממני להדביק את הפלט או לספר במשפט או שניים מה ראיתי. אחר כך קשר את מה שראיתי למושג מהפרק במשפט אחד, ועבור לפעולה הבאה. אל תכתוב בשבילי את הקוד — את זה עושה הסוכן ב-Cursor.
2. פעולה 1 — הכנה: ב-Git Bash:
mkdir -p ~/ai_lab/data
cd ~/ai_lab
git init
ליצור בפנקס הרשימות (touch data/stroop.csv ואז notepad data/stroop.csv) את הקובץ: שורת הכותרת id,condition,rt ושמונה שורות (2 נבדקים, 2 ניסויים בכל תנאי) עם מספרים שקל לחשב בראש. לעשות commit ראשון.
3. פעולה 2 — מפרט: לכתוב בפנקס הרשימות קובץ spec.txt עם חמשת החלקים (קלט, מבנה, כללים, פלט, אילוצים), ולחשב בראש את הממוצע הצפוי לכל תנאי. commit.
4. פעולה 3 — צעד ראשון: לפתוח את התיקייה ב-Cursor ולבקש מהסוכן רק: לקרוא את spec.txt ולכתוב סקריפט שטוען את הנתונים ומדפיס את מספר השורות ואת שמות העמודות. לקרוא את ה-diff לפני האישור, להריץ בטרמינל, ואם הפלט נכון — commit.
5. פעולה 4 — צעד שני: לבקש ממוצע זמן תגובה לכל תנאי, להשוות לחישוב שעשיתי בראש, ו-commit.
6. פעולה 5 — שגיאה: לשנות ביד בסקריפט את rt ל-RT, להריץ, ולתת לסוכן את ה-traceback המלא עם בקשה להסביר את הסיבה בלי לשנות קוד. לבסוף להחזיר את הקובץ עם git restore ושם הקובץ.
7. פעולה 6 — rollback: לבקש מהסוכן שינוי גדול ומיותר ("תכתוב מחדש את כל הסקריפט ותוסיף גרף"), לאשר, ואז להריץ git status ו-git diff, לחזור לנקודה התקינה עם git restore . ולמחוק קבצים חדשים שנוצרו. לוודא עם git status שהכול נקי.
8. בסוף, הצג טבלה קצרה: לכל פעולה, המושג שהיא המחישה (מפרט, Human-in-the-Loop, diff, Iterative Refinement, traceback, שורש הבעיה, rollback), ושאל אותי במשפט אחד מה הפתיע אותי. כתוב ששלב ההתנסות הסתיים.

המטלה השבועית (שבוע 12)

השבוע עובדים עם סוכן קוד (Cursor, או Claude Code / GitHub Copilot) בתוך מאגר Git, על הניתוח של heart.csv משבוע 11. כדאי לעשות קודם את היחידה „התנסות: פרויקט קטן עם סוכן״.

קובצי נתונים: heart.csv

חלק א - הכנת הפרויקט

  1. צרו תיקיית פרויקט חדשה ובתוכה תיקיית data, העתיקו אליה את heart.csv, והפכו את התיקייה למאגר Git (git init).
  2. צרו קובץ .gitignore שמוציא מהמעקב את תיקיית data ואת הקובץ .env. כתבו בהערה: למה לא מעלים את הנתונים ואת הסודות ל-GitHub?
  3. הוסיפו את המפרט משבוע 11 (spec.txt), וכתבו קובץ הנחיות לסוכן (AGENTS.md או Cursor Rules) עם לפחות ארבעה כללים, ובהם: לא לשנות קבצים בתיקיית data. עשו commit.

חלק ב - עבודה עם הסוכן

  1. בקשו מהסוכן לכתוב את הניתוח לפי המפרט, צעד אחד בכל פעם: טעינה, הסרת כפילויות, טבלה מסכמת וגרף. לפני כל אישור קראו את ה-diff; אחרי כל צעד הריצו, בדקו, ועשו commit עם הודעה שמתארת את הצעד.
  2. בקשו מהסוכן שינוי גדול ומיותר (למשל: „תכתוב מחדש את כל הסקריפט ותוסיף שלושה גרפים״). אחרי שסיים, הריצו git status ו-git diff, חזרו לנקודה התקינה האחרונה עם git restore, ומחקו קבצים חדשים שנוצרו. ודאו עם git status שהכול נקי.
  3. העלו את המאגר ל-GitHub (כמו בשבוע 7), ובדקו באתר ש-data ו-.env לא שם.

חלק ג - סודות ופרטיות

  1. צרו קובץ .env עם מפתח מדומה (MY_API_KEY=not-a-real-key). כתבו קוד שקורא אותו כמשתנה סביבה ומדפיס רק את מספר התווים שלו — לא את המפתח עצמו. ודאו עם git status ש-.env לא מופיע.
  2. כתבו בהערה (3–5 משפטים): אילו נתונים מהמחקר שלכם (או ממחקר שאתם מכירים) אסור לתת לסוכן, ואיך הייתם עובדים איתו בכל זאת?

בונוס (רשות):

  1. פנו למודל שפה מתוך סקריפט פייתון דרך API (ראו את הפרק על API בספר הפייתון), כשהמפתח שמור רק ב-.env.

פקודות הטרמינל לפי סדר המטלה. בבדיקה: ב-git log רואים commit לכל צעד עם הודעה ברורה; ב-GitHub אין את data ואת .env; ב-git status בסוף חלק ב מופיע „working tree clean״.

#### PART A: SET UP THE PROJECT ####

mkdir -p ~/heart_ai/data
cd ~/heart_ai
cp ~/Downloads/heart.csv data/      # the data stays local
git init

# .gitignore: the data and the secrets are never tracked
printf 'data/\n.env\n' > .gitignore
cat .gitignore

# the spec from week 11, and the rules file for the agent
cp ~/Downloads/spec.txt .
notepad AGENTS.md                   # at least four rules, e.g. "Never modify files in data/"
git add .gitignore spec.txt AGENTS.md
git commit -m "Spec, agent rules and gitignore"


#### PART B: AFTER EACH STEP OF THE AGENT ####

git status                          # which files changed
git diff                            # which lines changed (q to quit)
git add analysis.py
git commit -m "Load the data and print its shape"


#### PART B: UNDO THE BIG UNNEEDED CHANGE ####

git status                          # analysis.py modified, plot_all.py untracked
git diff analysis.py
git restore analysis.py             # back to the last commit
rm plot_all.py                      # a new file the agent created
git status                          # "nothing to commit, working tree clean"
git log --oneline


#### PART B: UPLOAD TO GITHUB (as in week 7) ####

git remote add origin https://github.com/<user>/heart_ai.git
git branch -M main
git push -u origin main


#### PART C: THE SECRET STAYS LOCAL ####

echo 'MY_API_KEY=not-a-real-key' > .env
git status                          # .env is not listed: .gitignore works
