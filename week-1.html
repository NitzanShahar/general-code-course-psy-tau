הנחיה למתרגל AI

אני סטודנט/ית לתואר שני בפסיכולוגיה, עובד/ת על Windows, ומתחיל/ה ללמוד תכנות. בשיעור זה ארצה להכיר את "השחקנים" שבתוך המחשב: החומרה, מערכת ההפעלה והתוכנות, ולראות אותם עובדים על המחשב שלי. אני רוצה הסבר מדויק אבל תמציתי, בלי מונחים שלא הסברת.
1. הסבר את שלושת רכיבי החומרה, עם סדרי גודל ועם האנלוגיה של מטבח:
(א) אחסון (Storage, כונן SSD או דיסק קשיח): המחסן. מאות GB עד כמה TB. המידע נשמר בו גם כשמנתקים את החשמל, אבל הוא איטי יחסית.
(ב) זיכרון עבודה (RAM): משטח העבודה. בדרך כלל 8 עד 32 GB. מהיר פי מאות עד אלפים מהאחסון, אבל ברגע שהחשמל נכבה, כל מה שעליו נמחק.
(ג) מעבד (CPU): הטבח. הוא יודע לבצע רק פעולות פשוטות מאוד — חיבור, השוואה, העברת מספר ממקום למקום — כתובות בשפת מכונה (machine code: רצפים של 0 ו-1), אבל מבצע מיליארדים מהן בשנייה.
2. הסבר מהי מערכת ההפעלה (Operating System, או OS: אצלי Windows; אצל אחרים macOS או Linux): התוכנה הראשית, שמנהלת את המחשב ומתווכת בין כל התוכנות לבין החומרה. המעבד לא יודע בעצמו לקרוא קובץ מהאחסון, ותוכנה לא ניגשת ישירות לחומרה: מערכת ההפעלה מחליטה איזו תוכנה מקבלת זמן מעבד ומקום ב-RAM, קוראת וכותבת קבצים באחסון, ומעבירה את מה שאני מקליד/ה ואת מה שמוצג במסך לתוכנה הנכונה.
3. הסבר מהי תוכנה (Software): קובץ באחסון שמכיל רצף ארוך של הוראות למעבד, בשפת מכונה (למשל calc.exe או notepad.exe). כל עוד הוא מונח באחסון, הוא לא עושה כלום. "לפתוח תוכנה" פירושו שמערכת ההפעלה מעתיקה את הקובץ מהאחסון ל-RAM, ומורה למעבד להתחיל לבצע את ההוראות שבו. תוכנה שרצה כרגע נקראת תהליך (process). הסבר גם למה זה חשוב למחקר: כשקוד טוען קובץ נתונים, נוצר עותק שלו ב-RAM, ושינויים בעותק לא משנים את הקובץ באחסון עד ששומרים.
4. התנסות — מנהל המשימות (Task Manager): בקש ממני לפתוח אותו עם Ctrl+Shift+Esc. בלשונית Performance (ביצועים) להסתכל על CPU, Memory (זה ה-RAM) ו-Disk (זה האחסון): כמה RAM יש במחשב, וכמה ממנו בשימוש עכשיו. אחר כך, בלשונית Processes (תהליכים), למצוא את התוכנות שפתוחות אצלי, ולראות כמה זיכרון כל אחת תופסת. בקש ממני לספר לך מה ראיתי, וקשר כל דבר שראיתי לרכיב שהסברת.
5. בקש ממני להשאיר את מנהל המשימות פתוח בצד המסך עד סוף השבוע: ביחידות הבאות נראה בו תוכנות שאני מפעיל/ה נכנסות לזיכרון. סכם בשלוש שורות: אחסון ← מערכת הפעלה ← RAM ← מעבד. כתוב ששלב הלימוד הסתיים.
הצג את השלבים האלו אחד אחד לפי הסדר. אחרי כל שלב עצור וחכה שאכתוב „המשך״ או שאדביק לך את מה שקיבלתי. בשיעור הזה מסבירים ומתנסים: אל תשאל אותי שאלות בוחנות ואל תיתן לי תרגילים נוספים — השאלות נמצאות ביחידה „שאלות פתוחות״ בסוף השבוע. אם משהו לא עובד אצלי, עזור לי לתקן לפני שממשיכים.

קוד 1.2מהו קובץ: bits, bytes, encoding ו-plain text

הנחיה למתרגל AI

אני סטודנט/ית לתואר שני בפסיכולוגיה, עובד/ת על Windows, ומתחיל/ה ללמוד תכנות. בשיעור זה ארצה להבין מה יש באמת בתוך קובץ, איך המחשב הופך אפסים ואחדים לאותיות, ולמה למדע חשוב לשמור נתונים כטקסט גולמי. אני רוצה הסבר מדויק אבל תמציתי.
1. הסבר שבאחסון כל דבר נשמר כרצף של מצבים פיזיים, שכל אחד מהם יכול להיות באחד משני מצבים: 0 או 1. כל 0 או 1 כזה נקרא ביט (bit). שמונה ביטים הם בייט (byte), ובבייט אפשר לייצג 256 ערכים שונים (0 עד 255). כל קובץ, בלי יוצא מן הכלל — מסמך, תמונה, תוכנה — הוא רצף של בייטים. תן סדרי גודל: KB הוא אלף בייטים, MB מיליון, GB מיליארד.
2. הסבר מהו encoding (קידוד): "מילון" מוסכם שקובע איזה מספר מייצג איזו אות. ASCII, משנות השישים, קבע למשל שהבייט שערכו 65 הוא האות A — אבל כיסה רק אנגלית. היום משתמשים כמעט תמיד ב-UTF-8: מילון עולמי שכולל עברית, סינית ואימוג'ים. ב-UTF-8 אות באנגלית תופסת בייט אחד, ואות בעברית שני בייטים. הסבר שתוכנה שקוראת קובץ טקסט צריכה לדעת באיזה קידוד הוא נכתב, ושמכאן מגיע ה"ג'יבריש" שרואים לפעמים במקום עברית.
3. הסבר את ההבדל בין שני סוגי קבצים:
(א) קובץ plain text (טקסט גולמי), כמו .csv, .txt, ובהמשך גם קובצי קוד כמו .py ו-.R: כל הבייטים בו מייצגים תווים לפי הקידוד, ותו לא. כל תוכנה בעולם יודעת לפתוח אותו, גם בעוד 30 שנה — וזה יתרון עצום למדע: הנתונים לא תלויים בתוכנה מסוימת.
(ב) קובץ בפורמט של תוכנה מסוימת, כמו .xlsx של Excel או .docx של Word: חוץ מהתוכן הוא מכיל מבנה, עיצוב, גופנים והגדרות, והכול ארוז ודחוס (קובץ xlsx הוא בעצם תיקייה דחוסה, zip, של כמה קבצים). רק תוכנה שמכירה את הפורמט יודעת לפענח אותו.
הסבר גם שהסיומת (extension: .csv, .xlsx) היא רק חלק מהשם: רמז ל-Windows איזו תוכנה לפתוח. שינוי הסיומת לא משנה אף בייט בתוכן.
4. התנסות — הכנה: בקש ממני להפעיל הצגת סיומות בסייר הקבצים (File Explorer): View > Show > File name extensions. הסבר שמעכשיו נראה תמיד את השם המלא של כל קובץ.
5. התנסות — Excel מול CSV: בקש ממני לפתוח את Excel, לכתוב בתא A1 את המספר 1, ולשמור את הקובץ פעמיים, באותה תיקייה (למשל בשולחן העבודה):
(א) Save As, בסוג Excel Workbook, בשם one.xlsx;
(ב) Save As, בסוג CSV UTF-8 (Comma delimited), בשם one.csv.
לסגור את Excel. אחר כך לפתוח כל אחד מהם בפנקס הרשימות (Notepad): קליק ימני על הקובץ > Open with > Notepad. ולבסוף, בקליק ימני > Properties, לבדוק את הגודל של כל קובץ בבייטים. בקש ממני לספר מה ראיתי בכל אחד. אחר כך הסבר: ה-CSV מכיל כמה בייטים בודדים — הספרה 1, סימן ירידת שורה, ואולי שלושה בייטים בהתחלה שמסמנים "אני UTF-8" — ולכן פנקס הרשימות מציג אותו בדיוק. ה-xlsx מכיל אלפי בייטים של מבנה דחוס; פנקס הרשימות מניח שזה טקסט, מתרגם כל בייט לתו לפי הקידוד, ומקבל ג'יבריש. האותיות PK בתחילתו הן החתימה של קובץ zip.

אני סטודנט/ית לתואר שני בפסיכולוגיה, עובד/ת על Windows, ומתחיל/ה ללמוד תכנות. בשיעור זה ארצה לכתוב את הסקריפט הראשון שלי, לשמור אותו בתיקיית המחקר שלי ולהריץ אותו מהטרמינל — ולהבין את כל השרשרת, מהמקלדת ועד המעבד. Git Bash, R ופייתון מותקנים אצלי.
1. הסבר שעד עכשיו עבדנו אינטראקטיבית: כתבנו שורה, קיבלנו תשובה, ומה שכתבנו נעלם כשיצאנו. למדע צריך script (סקריפט): קובץ plain text שמכיל קוד, נשמר באחסון, מתעד בדיוק מה עשינו, ומאפשר לכל חוקר להריץ אותו שוב ולקבל אותה תוצאה.
2. התנסות — יצירת הקובץ: בקש ממני, ב-Git Bash, להריץ:
cd my_science_project
pwd
touch experiment.py
notepad experiment.py
הסבר: cd מעבירה אותי לתיקיית המחקר (זוכר/ת? כל פתיחה של Git Bash מתחילה בתיקיית הבית); touch יוצרת קובץ ריק בתיקיית העבודה; notepad פותחת אותו בפנקס הרשימות — שנמצא, כמו המחשבון, בתיקייה שב-PATH. כך הקובץ נוצר בדיוק במקום הנכון ובשם הנכון, בלי שפנקס הרשימות יוסיף לו .txt. עצור וחכה.
3. בקש ממני לכתוב בפנקס הרשימות שלוש שורות:
a = 5
b = 10
print("The result is:", a + b)
לשמור עם Ctrl+S, ולהסתכל בשורת המצב בתחתית החלון: כתוב שם UTF-8 — הקידוד שבו הקובץ נשמר. הסבר בקצרה מה כל שורה עושה: = שומר ערך תחת שם, ו-print מדפיסה. עצור וחכה.
4. התנסות — הרצה: בקש ממני לחזור לטרמינל ולהריץ:
ls
python experiment.py
הסבר: ls מראה שהקובץ נמצא בתיקיית העבודה. בשורה השנייה המילה הראשונה היא שם ה-interpreter, והשנייה היא שם קובץ הטקסט שהוא יקרא. הפלט צריך להיות The result is: 15. עצור ובקש להדביק.
5. אותו דבר ב-R: בקש ממני ליצור באותה דרך קובץ בשם experiment.R, עם השורות:
a = 5
b = 10
cat("The result is:", a + b, "\n")
ולהריץ:
Rscript experiment.R
הסבר ש-R ו-Rscript הן שתי תוכנות של אותו interpreter: R פותחת שיחה ומחכה לשורות ממני, ו-Rscript קוראת קובץ, מבצעת אותו ומסיימת. הסבר ש-cat ב-R היא הדרך להדפיס כמה דברים בשורה אחת, ו-"\n" הוא ירידת שורה. עצור ובקש להדביק.
6. רגע ה"אהא": הצג את הסיכום המלא של מה שקרה כשהקשתי Enter על python experiment.py, כרשימה ממוספרת:
(א) הטרמינל העביר את השורה ל-bash.
(ב) bash פירק אותה למילים: python ו-experiment.py, וחיפש תוכנה בשם python בתיקיות של PATH.
(ג) כשמצא, ביקש ממערכת ההפעלה להריץ אותה; מערכת ההפעלה העתיקה את ה-interpreter מהאחסון ל-RAM, והוא התחיל לרוץ כתהליך.
(ד) ה-interpreter חיפש את experiment.py — ומצא אותו, כי זה שם בלי נתיב והייתי בתיקיית העבודה הנכונה.
(ה) הוא קרא את הקובץ: בייטים של טקסט גולמי, שתורגמו לאותיות לפי UTF-8.
(ו) הוא בדק שהקוד תקין לפי חוקי השפה, ותרגם שורה אחר שורה לפעולות שהמעבד ביצע: החיבור 5 + 10 קרה במעבד.
(ז) print העבירה את התוצאה למערכת ההפעלה, שהציגה אותה בחלון הטרמינל.
(ח) התהליך הסתיים, הזיכרון שוחרר, ו-bash הציג שוב $.
הסבר שהתהליך של פייתון היה קצר מדי כדי לראות אותו במנהל המשימות, אבל עבר בדיוק את אותו מסלול כמו המחשבון. כתוב ששלב הלימוד הסתיים, ושהשבוע נסגר בשאלות הפתוחות ביחידה הבאה.
